Synora — Study & Viva Notes

Everything behind this project in one page: what was built, why each decision was made, and how it works in code. Use the search box to jump to a topic, tick sections off as you learn them, and finish with the quiz and the viva questions at the bottom.

This file is completely standalone — no stylesheet, no script file, no internet. Open it straight from disk and it works.

▸1IntroductionRead

Synora is a student productivity web application. It brings the things a student juggles across notebooks, group chats and memory — assignments, deadlines, timetable, attendance and grades — into one workspace that lives in the browser.

What

A single-page-per-feature web app with tasks, a calendar, quick notes, a timetable, attendance tracking, CGPA calculation, achievements and notifications, behind a sign-up / sign-in flow.

Why

Students already have all this information; what they don't have is one place where it adds up. Six apps that each know a fifth of your week can't tell you that you're two classes from dropping below 75%.

How

Plain HTML5, CSS3 and vanilla JavaScript. No framework, no build step, no server. All data is kept in the browser's localStorage, namespaced per user.

The one-sentence architecture

Every page loads storage.js (the only file that touches localStorage), then app.js (the shell — sidebar, topbar, modals, notifications), then one feature script that renders that page.

storage.js → avatars.js → app.js → <feature>.js data faces shell the page
Say this clearly in a viva. The project is deliberately framework-free. Every piece of state management, routing, templating and event handling here is written by hand — which is the point of the exercise. It is not "a React app without React"; it is built the way the platform is built.
▸2Problem statementRead

A student's academic life is scattered across tools that don't talk to each other:

  • Deadlines live in a group chat and are found again by scrolling.
  • Attendance is a number the department knows and the student estimates.
  • CGPA is worked out on a calculator, once, the night before it matters.
  • The timetable is a photo of a printed sheet.

The cost is not that any single item is hard. It is that nothing is connected, so no tool can answer the question a student actually has:

"Can I skip tomorrow's DBMS lecture?"

Answering that needs the timetable, the attendance record and the target percentage together. Synora exists so those three facts sit in one data model and one screen can do the arithmetic.

▸3ObjectivesRead

Functional

  • Create an account, sign in, and keep each account's data completely separate.
  • Personalize a workspace: avatar, program, semester, subjects, attendance target, theme.
  • Manage tasks with priorities, deadlines and status; view them on a calendar.
  • Keep quick notes and a weekly timetable.
  • Track attendance per subject and say how many classes can safely be missed.
  • Compute a credit-weighted CGPA, including failure states.
  • Unlock achievements and raise notifications from the data, not from a fixed list.

Technical

  • HTML5, CSS3 and vanilla JavaScript only — no framework, no libraries, no build.
  • One data layer; no other file touches localStorage directly.
  • One source of truth for subjects, referenced everywhere by id.
  • Responsive from 320px to desktop; light and dark themes.
  • Keyboard-operable and screen-reader-labelled throughout.
A good objectives answer names a constraint. "No framework" is the interesting one: it forces explicit state, manual DOM updates and hand-written event delegation — all of which this project has to solve visibly rather than delegate.
▸4ArchitectureRead
What

Three layers: a data layer, a shell, and per-page feature modules. Pages are real HTML files; navigation is ordinary links, not a router.

Why

Multi-page keeps each file small and means the browser does the routing, the history and the back button correctly for free. A hand-rolled SPA router would be code that only re-implements what the browser already does.

How

Scripts are loaded with defer in dependency order, and app.js announces readiness with a custom event so feature scripts know when the shell exists.

Load order and the readiness event

<!-- every page in app/ loads these, in this order -->
<script src="../scripts/storage.js" defer></script>
<script src="../scripts/avatars.js" defer></script>
<script src="../scripts/app.js"     defer></script>
<script src="../scripts/tasks.js"   defer></script>

defer means each script downloads in parallel but executes in document order, after the HTML is parsed. So storage.js has always defined Synora.store before app.js runs.

The subtle part is the handover to the feature script:

// app.js — the LAST thing boot() does
document.dispatchEvent(new CustomEvent("synora:ready"));

// tasks.js — registered before that ever fires
document.addEventListener("synora:ready", initPage);
The bug this avoids. app.js must wait for DOMContentLoaded before dispatching, not fire immediately. Deferred scripts run while readyState === "interactive", and tasks.js executes after app.js — so dispatching immediately would send the event into an empty room, before any listener existed. Waiting one tick guarantees every feature script has registered.

Why the shell is built in JavaScript

The sidebar and topbar are generated by app.js from one NAV array rather than copied into eleven HTML files. Adding a page means adding one object; the alternative is eleven files that drift apart the first time one is edited.

▸6CSSRead
What

A token-driven design system: custom properties for colour, type, spacing and shadow, then components built only from those tokens.

Why

Naming a value once means changing it once. It is also what makes dark mode a redefinition of variables rather than a second stylesheet.

How

:root holds the light palette; [data-theme="dark"] redefines the same names; every component references var(--…) and never a raw hex.

Custom properties and dark mode

:root {
  --color-bg:      #FAF9F7;
  --color-surface: #FFFFFF;
  --color-text:    #22252B;
  --color-brand:   #53655C;
}

[data-theme="dark"] {
  /* same names, different values — every component follows */
  --color-bg:      #16181C;
  --color-surface: #1D2025;
  --color-text:    #E7EAE8;
  --color-brand:   #8FA697;
}

.card { background: var(--color-surface); color: var(--color-text); }

Flipping one attribute on <html> re-themes the entire app, because no component knows a literal colour.

Flexbox vs Grid — and when the difference bites

Flexbox lays out along one axis and is content-driven. Grid defines the tracks first and places content into them. The landing navbar is the case where only Grid gives the right answer:

.nav {
  display: grid;
  /* outer tracks are EQUAL, which is what centres the middle one */
  grid-template-columns: minmax(0, 1fr) auto minmax(0, 1fr);
  align-items: center;
}

With flexbox and margin-left: auto, the links land wherever the logo and the buttons leave them — centred only by coincidence. With 1fr auto 1fr the centre track is centred in the header no matter how wide the outer two grow.

minmax(0, 1fr), not 1fr. A track sized 1fr is really minmax(auto, 1fr): it refuses to shrink below its content's minimum width. Put a wide table or a long code block in it and the track pushes the whole page wider than the viewport, producing horizontal scroll on the body. minmax(0, 1fr) removes that floor so the content scrolls inside its own box. This caused two real overflow bugs in this project.

Centring is geometry and optics

The grid above centred the nav links perfectly — and they still looked pushed right, because a 109px logo on one side was facing a 273px stack of buttons on the other. The fix was not more CSS but rebalancing the two clusters: the theme toggle moved next to the logo, and "Sign in" became a text link. The maths never changed; the picture did.

Other CSS worth naming in a viva

  • Cascade layers of specificity: a single :focus-visible rule gives every control a ring, so none can silently lose it.
  • color-mix(): the translucent sticky header is color-mix(in srgb, var(--color-bg) 82%, transparent) — it tracks the theme variable, which a hard-coded rgba() cannot.
  • clamp(): fluid headings, clamp(1.75rem, 4vw, 2.25rem), without a media query.
  • aspect-ratio: keeps avatar cells square at any grid width.
  • prefers-reduced-motion: animations are switched off for anyone who asks the OS to.
A real bug from this project. base.css gives every <svg> a max-width: 100%. Inside a shrink-to-fit grid that is circular — the SVG waits for the container's width and the container waits for the SVG's — and the progress ring collapsed to zero width. The rotated 0×128 box still measured 128 across, so it could look nearly right while being wrong. Fix: state the wrapper's size explicitly instead of inferring it.
▸7JavaScriptRead
What

Vanilla ES5-style JavaScript organised into IIFE modules, one per feature, communicating through a single global Synora namespace.

Why

No bundler means no import syntax, so modules are made with functions and closures. One namespace keeps eleven scripts from polluting window with eleven names each.

How

Each file is (function () { "use strict"; … })(); and attaches only its public API to Synora.

The module pattern

(function () {
  "use strict";

  // private — nothing outside this file can reach `rows`
  var rows = [];

  function setCounts(id, held, attended) { /* … */ }

  // public — the ONLY thing exposed
  Synora.attendance = { setCounts: setCounts };
})();

This is a closure: setCounts keeps access to rows after the outer function has returned, while nothing else can see it. That is encapsulation without a class or a module system.

Event delegation

The attendance grid re-renders itself on every click. Binding listeners to the buttons would attach them to elements that are about to be destroyed. So one listener sits on the container that survives:

subjectsEl.addEventListener("click", function (e) {
  var step = e.target.closest("[data-step]");
  if (step) {
    applyStep(step.getAttribute("data-for"),
              step.getAttribute("data-which"),
              Number(step.getAttribute("data-step")));
    return;
  }
  var edit = e.target.closest("[data-edit]");
  if (edit) { openEdit(edit.getAttribute("data-edit")); }
});

Events bubble from the clicked element up to the document, so the container sees clicks on children that did not exist when the listener was added. e.target is what was clicked; closest() walks up to the element carrying the data attribute.

Lesson learned the hard way. Never bind a listener inside a function that re-renders its own container — each render adds another copy, and handlers fire two, three, four times. Bind to the surviving wrapper, or bind once outside the render.

Escaping — a security habit, not a formality

escapeHTML: function (str) {
  return String(str == null ? "" : str)
    .replace(/&/g, "&amp;")
    .replace(/</g, "&lt;")
    .replace(/>/g, "&gt;")
    .replace(/"/g,  "&quot;")
    .replace(/'/g,  "&#39;");
}

Any user-typed value — a subject name, a task title, a note — goes through this before it is concatenated into innerHTML. Without it, a task called <img src=x onerror=alert(1)> would execute. That is stored XSS, and the fact that the "attacker" here is the user themselves does not make writing the escape optional.

▸8LocalStorage & the data layerRead
What

localStorage is a browser key–value store: strings only, about 5–10 MB per origin, synchronous, and persistent until explicitly cleared.

Why

It is the only way to keep data between page loads with no server. Synora has no backend, so this is the database.

How

One file — storage.js — wraps it. Every other script goes through Synora.store and never calls localStorage itself.

Why one file owns it

If eleven scripts each called localStorage.setItem, eleven scripts would each need to agree on key names, JSON shape, defaults and error handling. Funnelling through one module means the shape is defined once and a missing or corrupted value is handled once.

function readJSON(key, fallback) {
  try {
    var raw = localStorage.getItem(key);
    if (raw === null) return fallback;
    return JSON.parse(raw);
  } catch (err) {
    // corrupted or non-JSON — fall back rather than crash the page
    console.warn("Synora: could not parse", key, err);
    return fallback;
  }
}

Keys and per-user namespacing

GLOBAL (shared by the browser) synora-users every account synora-session { username } — who is signed in synora-theme "light" | "dark" PER USER synora:<username>:<collection> synora:arsh2309:subjects ← the academic source of truth synora:arsh2309:tasks synora:arsh2309:notes synora:arsh2309:timetable synora:arsh2309:attendance synora:arsh2309:cgpa synora:arsh2309:achievements synora:arsh2309:notifications synora:arsh2309:profile synora:arsh2309:meta

The namespace is what makes user isolation work. Two accounts on one browser write to different keys, so signing out and in as someone else shows their data and only their data. There is no filtering step to forget.

Forward compatibility

Object-shaped collections gain any key added to DEFAULTS after the record was first written, so an account created by an older build keeps working:

var fallback = defaultFor(collection);
if (isPlainObject(fallback) && isPlainObject(value)) {
  Object.keys(fallback).forEach(function (k) {
    if (!(k in value)) value[k] = fallback[k];
  });
}

The same idea appears in subjects.all(): a subject saved before trackAttendance existed is read as tracked, because that is what it was doing at the time. An upgrade must never silently empty somebody's attendance page.

Limits worth stating honestly. localStorage is per-browser and per-device — it does not sync, and clearing browsing data deletes it. It is synchronous, so a very large write blocks the main thread. It stores strings only, which is why everything is JSON.stringifyd. And it is readable by any script on the origin, which is why nothing genuinely secret should ever go in it.
▸9Subjects — the source of truthRead
What

One canonical list of subjects. Attendance, CGPA and the timetable all reference a subject by id and never store its name.

Why

The alternative — each module keeping its own copy of "DBMS" — means renaming a subject in one place leaves the other three pointing at a name that no longer exists.

How

store.subjects in storage.js owns the list; remove() cascades to every dependent record.

The record

{
  id:              "dbms",      // stable, never re-used
  name:            "DBMS",      // display only
  credits:         4,           // used by CGPA
  trackAttendance: true         // used by Attendance only
}
subjects ──┬── attendance { subjectId, total, attended } ├── cgpa { subjectId, grade } └── timetable { subjectId, day, startTime, endTime }

What that buys

  • You pick subjects from a dropdown; you never retype a name.
  • Renaming OOPS to Object Oriented Programming updates the attendance cards, both charts and the timetable at once — because none of them stored the name.
  • Deleting a subject removes its attendance row, its grade and its classes with it, so nothing is left pointing at a subject that no longer exists.
  • Credits live in one place, so the CGPA and the subject list cannot disagree.
// removing a subject cascades — no orphaned references
remove: function (id) {
  update("subjects",   function (l) { return l.filter(function (s) { return s.id !== id; }); });
  update("attendance", function (l) { return l.filter(function (a) { return a.subjectId !== id; }); });
  update("timetable",  function (l) { return l.filter(function (c) { return c.subjectId !== id; }); });
  update("cgpa", function (c) {
    c.subjects = c.subjects.filter(function (s) { return s.subjectId !== id; });
    return c;
  });
}
▸10trackAttendance — optional per subjectRead

When a subject is added — in onboarding or in Settings — Synora asks one extra question:

Record attendance for this subject? ( ) Yes ( ) No
What

A boolean stored on the subject that decides whether it appears in Attendance.

Why

Some subjects genuinely don't take a register — a one-credit elective, an audit. Forcing them onto the attendance page produced a permanent 0% for a class nobody counts, and a recurring "… is at 0%" notification for it.

How

subjects.tracked() is the single filter, and derive.attendance() walks the tracked subjects rather than the stored attendance rows.

The important design move

Attendance is driven by the subject list, not by the stored attendance rows:

attendance: function () {
  var counts = {};
  store.get("attendance").forEach(function (a) { counts[a.subjectId] = a; });

  // walk the SUBJECTS — an untracked one can never appear
  var rows = store.subjects.tracked().map(function (s) {
    var a = counts[s.id] || {};
    var total    = Math.max(0, Number(a.total) || 0);
    var attended = clamp(Number(a.attended) || 0, 0, total);
    return {
      subjectId: s.id, subject: s.name, total: total, attended: attended,
      pct: total ? (attended / total) * 100 : 0,
      recorded: total > 0
    };
  });
  // …
}

Because the subjects drive it, a subject whose tracking is switched off leaves the page, the chart and the warnings at the same instant — there is no stale row to clean up and no second filter to remember. A newly added subject appears immediately at 0/0 with working + buttons.

This is general behaviour, not a demo special case. The demo account happens to have two untracked subjects, but nothing in the code mentions that account. Any user who answers "No" gets the same result.
▸11AuthenticationRead
What

Sign up creates an account in synora-users; sign in verifies it and writes synora-session. Every app page checks that session and redirects to the sign-in page if it is missing.

Why

Without accounts there is no per-user data, and per-user data is the whole point of the namespaced storage.

How

auth.js serves both pages, choosing its flow by which form id is present. Passwords are hashed with cyrb53 before storage.

The flow

Create account ↓ Account written to synora-users (hashed password) Session written to synora-session Profile row created (empty workspace) ↓ CONFIRMATION SCREEN ← waits here ↓ User chooses: [ Personalize ] or [ Go to dashboard ]

Validation

FieldRule
First / last nameRequired, stored separately — this is what makes initials correct
Email/^[^\s@]+@[^\s@]+\.[^\s@]{2,}$/ — deliberately permissive
Username3–20 characters, letters/numbers/underscore, must be unique
Password8+ characters, at least one letter and one number

The email pattern is loose on purpose: anything stricter starts rejecting addresses that are perfectly valid. Validation exists to catch typos, not to prove an address is real — only sending mail can do that.

Why the sign-in page shows no session state

Earlier the page displayed "Signed in as Manan Kochhar — Sign out" whenever a session existed. That was removed, for two reasons:

  • It answered a question nobody standing on a sign-in page asked.
  • It put the account holder's real name on a screen anyone can open.
Removing the message is not removing the session. The session is still written on sign-in and still read by every app page — it is what the sidebar, Settings and the profile menu display. Only the display of it on the sign-in page was removed. Signing out lives in the app's profile menu, which is where a signed-in person looks for it.

Why the confirmation screen does not auto-redirect

It used to show for 900 ms and then navigate. That is not a choice; it is an announcement on the way somewhere the app had already decided to go. It now offers two buttons and waits. Both are ordinary <a href> links, so neither can be broken by a script that failed to run.

Security, stated honestly. Hashing here is obfuscation, not security. cyrb53 is a fast non-cryptographic hash with no salt; anyone with access to the browser can read localStorage. Real authentication needs a server, a slow salted hash (bcrypt/argon2) and a token. Never reuse a real password in this project.
▸12Onboarding / PersonalizationRead
What

Six steps that turn an empty account into a workspace: avatar, program & semester, subjects, attendance target, appearance, review.

Why

A brand-new workspace is empty by design, and an empty dashboard is a bad first impression. Asking six short questions produces a dashboard that already knows who you are and what you study.

How

onboarding.js keeps an explicit draft object and renders the current step from it; the DOM is a view of the state, never the state itself.

Avatar → Academic → Subjects → Attendance goal → Appearance → Finish

One question per step on purpose: the same six fields in a single long form reads as paperwork; split up, it reads as setup.

State is explicit

var draft = {
  step: 0,
  avatar: null,
  program: "",
  semester: "",
  subjects: [],            // each { id, name, credits, trackAttendance }
  targetAttendance: 75,
  appearance: "light"
};

Because the answers live in draft and not in whichever inputs happen to still be on screen, moving back and forth cannot lose one. The draft is also mirrored to synora:<username>:onboarding on every change, so reloading mid-setup returns you to the same step with the same answers. Finishing clears it.

Buttons

ButtonDoes
ContinueValidates the step; on failure shows an inline error and stays put. On success saves into draft, advances, updates the step indicator.
BackReads the current step's values first (so nothing typed is lost), then steps back. No validation — going back is not a commitment.
Skip for nowMoves past an optional step (only the avatar step is skippable).
Save & finish laterSaves everything entered and opens the dashboard without marking setup complete, leaving the draft in place.
Finish setupWrites the profile and the subject list, sets onboarded: true, clears the draft.
The bug that made all of this look broken. None of these buttons worked, and no avatar could be selected. The cause was one CSS line. The "You're all set." panel is position: fixed; inset: 0; z-index: 100 with opacity: 0, and it carries the hidden attribute — but the stylesheet also said display: grid, which overrides the browser's own [hidden] { display: none }. So an invisible full-screen sheet sat on top of the page swallowing every click. Nothing was wrong with the JavaScript; the clicks never reached it.

Fix: .ob-done[hidden] { display: none; }. The lesson is that hidden loses to any author display rule, and that "the button does nothing" is often a hit-testing problem, not a logic one — document.elementFromPoint(x, y) finds it in seconds.

Onboarding is offered, never forced

There used to be a guard that bounced anyone who hadn't finished setup back into it. That made both "Go to dashboard" and "Save & finish later" into buttons that returned you to where you just left. The guard now only checks whether you are signed in; the dashboard shows a Finish setting up your workspace card instead.

▸13The avatar systemRead
What

Twelve illustrated avatars, or your initials on one of six colours.

Why

A face makes a workspace feel like yours. Offering initials as a real option means nobody is forced to pick a cartoon that doesn't look like them.

How

The choice is stored as a small object naming the kind and the id; avatars.js renders whichever it is and falls back on its own.

{ type: "illustration", id: "avatar-03" }   // one of the twelve
{ type: "initials",     id: "sage" }        // initials on a colour
null                                        // nothing chosen → initials

It used to be a bare id string. That could only name one kind of avatar, so adding initials-with-a-colour meant the value had to describe which kind as well as which one. Old string values are still read, as illustration ids.

Licensing — answer this precisely

The illustrations are the Lorelei style from DiceBear, by the designer Lisa Wischofsky, released under CC0 1.0 (public domain — no attribution required, commercial use allowed).

Do not say "DiceBear avatars are CC0". That is wrong. DiceBear's library code is MIT, but each avatar style carries its own licence chosen by its artist. Several — Adventurer, Big Smile, Croodles, Micah, Personas and others — are CC-BY-4.0 and require visible credit. Only the licence of the style you actually use may be claimed. Synora uses one style, Lorelei, and relies only on its CC0 licence.

Downloaded once, committed to the repo

The twelve SVGs live in assets/avatars/ rather than being fetched from the DiceBear API at runtime. That matters here: they render with no network, nothing about the user is sent to a third party, and the grid cannot half-load in front of an examiner. Being vectors, 28px in the sidebar is as crisp as 96px in onboarding.

They were curated, not taken as the first twelve generated. Twenty-four were rendered and half were rejected — the squinting, scowling and otherwise odd expressions — leaving twelve friendly faces with genuinely different hair over rotating Synora-tinted backgrounds, all in one visual family so the grid reads as a set.

Initials come from exactly one function

initials: function (firstName, lastName) {
  var first = String(firstName || "").trim();
  var last  = String(lastName  || "").trim();

  // called with one combined string? split it
  if (!last && first.indexOf(" ") !== -1) {
    var parts = first.split(/\s+/);
    first = parts[0];
    last  = parts[parts.length - 1];
  }
  // FIRST letter of first name + FIRST letter of last name
  return ((first.charAt(0) || "") + (last.charAt(0) || "")).toUpperCase() || "S";
}
Manan Kochhar → MK (not MA) Arshpreet Kaur → AK

It is defined once in storage.js and used by the sidebar, topbar, dashboard, Settings and onboarding, so two screens can never disagree. Storing first and last name separately at sign-up is what makes this possible — from a single "Manan Kochhar" string you would be guessing.

▸14Task managementRead
What

Create, edit, complete and delete tasks with a title, subject, description, deadline, priority and status.

Why

Deadlines are the thing students most often lose track of, and a task list that knows the deadline can feed the calendar, the dashboard and the notification engine.

How

tasks.js renders from store.get("tasks"); every mutation writes back and then calls Synora.refresh().

{
  id: "tsk-1",
  title: "Submit SDE assignment 2",
  subject: "SDE",
  description: "Sprint planning write-up",
  deadline: "2026-08-19",          // local YYYY-MM-DD
  priority: "critical",             // critical | high | medium | low
  status: "in-progress",            // not-started | in-progress | completed
  createdAt: "…", completedAt: null
}

Derived, never stored

"Overdue", "due today" and "upcoming" are not fields. They are computed from the deadline every time, because a stored flag would be wrong the moment the clock passed midnight:

tasks.forEach(function (t) {
  if (t.status === "completed") { stats.completed++; return; }
  stats.pending++;
  var days = t.deadline ? daysUntil(t.deadline) : null;
  if (days === null) return;
  if (days < 0)       stats.overdue++;
  else if (days === 0) stats.dueToday++;
  else              stats.upcoming++;
});
Dates are handled as local, never UTC. new Date("2026-08-19") parses as UTC midnight, which in a positive timezone is still the 18th locally — so a task would show as due a day early. Synora parses YYYY-MM-DD into a local date explicitly with new Date(y, m - 1, d).

▸18AttendanceRead
What

Per-subject class counts, a percentage, and the answer to "how many can I miss?" or "how many must I attend?"

Why

The number a student actually needs is not the percentage — it is the count of classes between them and the rule.

How

Counts are stored as { subjectId, total, attended }; everything else is computed.

attendance % = attended / held × 100

The card

FEE [edit] [delete] Held − 39 + Attended − 32 + Attendance 82.05% You can miss 3 more classes and stay above 75%.
  • + / − handle the everyday correction of a count, updating the percentage, ring, chart and warnings immediately.
  • Edit is for the major changes — name, credits, whether attendance is recorded at all, and a direct correction of both numbers.
  • Delete removes the subject and everything pointing at it, naming what will go first.
  • Credits are not shown. They are a CGPA fact and say nothing about whether you turned up.
  • There is no "Track a subject" button. A subject is not something you add here; it is something you already have, which either takes a register or doesn't.

Two invariants, enforced in one place

function setCounts(subjectId, held, attended) {
  var h = Math.max(0, Math.round(Number(held) || 0));
  var a = clamp(Math.round(Number(attended) || 0), 0, h);
  // …write {subjectId, total: h, attended: a}…
}
held ≥ 0 0 ≤ attended ≤ held

Lowering held below attended pulls attended down with it, because a student cannot attend more classes than were held. Putting both rules in setCounts rather than in each button means the +, the − and the Edit dialog cannot disagree.

The two questions

// At or above target — how many can I still miss?
//   attended / (total + x) ≥ goal/100
canMiss = Math.max(0, Math.floor((attended * 100) / goal - total));

// Below target — how many in a row must I attend?
//   (attended + n) / (total + n) ≥ goal/100
need = Math.max(0, Math.ceil((goal * total - 100 * attended) / (100 - goal)));
Divide-by-zero is handled at the source. A subject with no classes yet would produce 0/0 = NaN, and NaN% on screen. The percentage is guarded at the one place it is computed — total ? (attended / total) * 100 : 0 — and the card shows "No classes recorded yet." rather than a misleading 0%.

The chart

  • Y axis fixed 0–100%, never scaled to the tallest bar. A percentage has a real ceiling, and a chart stretched to fit 83% makes 83% look like a full house.
  • X axis is the tracked subjects only.
  • The dashed target line reads profile.targetAttendance — it is never hard-coded to 75.
  • Bars below target turn red, and the chart carries a text summary for screen readers.

What

A credit-weighted grade point average across every subject, with three explicit failure states.

Why

CGPA is the number that follows a student around, and working it out by hand is exactly the kind of arithmetic a computer should do.

How

Grades are stored per subject; credits come from the subject record; the CGPA is computed on every render and never stored.

CGPA = Σ(credits × grade point) / Σ(credits)

The grading system

GradeMeaningPoints

B+Good7

Why the "Exam status" field was removed

There used to be a second dropdown beside the grade holding E1/E2/E3. That meant two controls describing one outcome, with nothing stopping them contradicting each other — a subject could read "A+" and "failed both" at the same time. The grade now carries the result on its own. The 4.0 US scale went at the same time: E1/E2/E3 are specific to this system, so offering them beside a US scale produced combinations that meant nothing.

A stated assumption. A failing grade earns zero grade points but still carries its credits into the denominator — the standard way a backlog drags an average down. This project has no university-specific rule to defer to, so the assumption is written down rather than left implied. Say this out loud in a viva; it shows you know it is a choice.

The split chart

Two kinds of result, so two directions. E1, E2 and E3 hang below the baseline because a failure is not a small grade — putting it on the same upward scale would say something false. They are never merged into one "E1/E2/E3" label: which examination was failed is the entire point of the distinction.

Internally the numbers are only bar heights (B → 1 … O → 5 upwards, E1 → 1 … E3 → 3 downwards); the axes show the letters students use, not the arithmetic.

CGPA and attendance are independent

Every subject appears on the CGPA page, including those with trackAttendance: false. Attendance is about registers; CGPA is about credits and grades. A subject can have no attendance record at all and still count fully.

▸26LimitationsRead

Being straight about what this does not do is part of presenting it well.

  • No backend. No server, no database, no API. Everything is frontend.
  • Not real authentication. Passwords are hashed with a fast, unsalted, non-cryptographic hash. This is obfuscation, not security — anyone with access to the browser can read localStorage. Never reuse a real password.
  • Per-device. Data lives in one browser on one device. It does not sync, and clearing browsing data deletes it.
  • Storage ceiling. localStorage holds roughly 5–10 MB; writes are synchronous and block the main thread.
  • The contact form sends nothing. It validates and confirms on the page; no email is delivered, and the UI says so.
  • The demo credential is sample data, not a security claim.
  • A stated CGPA assumption: failures score 0 points with credits still counted. That is a choice, not a universal rule.
  • Old grades are stranded. Values from before the grading system changed (C, P, F, or the old 4.0 scale) read as Not graded until re-picked. They are not deleted, but they do not contribute.
  • No collaboration — no sharing, no multi-device, no notifications outside the tab.
  • This notes file duplicates explanation on purpose. It is standalone, so it will not follow a change made in scripts/.

▸29Viva questions & answers (113)Read

113 questions and answers, grouped by topic, all based on the actual implementation rather than generic theory. Click a question to reveal its answer — the search box at the top filters these too.

HTML 10 questions

1What is semantic HTML and why does it matter?

Using elements for what they mean rather than how they look — <header>, <nav>, <main>, <section>, <button>. It gives screen readers real landmarks, improves SEO, and makes the markup readable. In Synora it also saves code: <details> is a working accordion with keyboard support, and a <label> wrapping a radio makes the whole avatar clickable with no JavaScript.

2Why is <!DOCTYPE html> required?

It puts the browser in standards mode. Without it, browsers fall back to quirks mode and emulate old, inconsistent box-model behaviour.

3What does defer do on a script tag?

The script downloads in parallel with HTML parsing and executes after parsing finishes, in document order. Synora relies on that ordering: storage.js has always defined Synora.store before app.js runs. async would break it, because async scripts run whenever they arrive.

4Why does theme.js load WITHOUT defer?

It must run before the first paint. If it ran late, a dark-mode user would see a white flash and then the page would turn dark — FOUC. Blocking for a few milliseconds is the right trade.

5What does novalidate do on a form?

It turns off the browser's built-in validation bubbles so the app can show its own inline messages instead. The required attributes stay for semantics; the messaging becomes ours.

6Difference between the hidden attribute and display: none?

hidden is a hint the browser implements as display: none in its default stylesheet — so any author display rule beats it. That exact clash caused Synora's biggest bug: .ob-done had hidden but also display: grid, leaving an invisible overlay that swallowed every click. The fix was an explicit .ob-done[hidden] { display: none; }.

7How do you associate a label with an input?

Either <label for="id"> matching the input's id, or by wrapping the input inside the label. Synora uses the wrapping form in the avatar picker so clicking the artwork checks the radio.

8Why do the avatar radios share one name?

Radios with the same name are mutually exclusive, enforced by the browser. All 18 options — 12 illustrations and 6 initials colours — share name="ob-avatar", so "choose exactly one avatar mode" needs no extra state.

9What is <datalist> for?

It attaches suggestions to a text input while still allowing free text. Onboarding uses it for the program field so common programs are one keystroke away without limiting anyone to the list.

10What does <output> give you?

It is an implicit live region, so its changes are announced by screen readers. Synora uses it for the attendance target slider and the stepper values.

CSS 16 questions

11What are CSS custom properties and why use them?

Variables declared as --name: value and read with var(--name). They cascade and can be redefined per selector, which is what makes dark mode a redefinition of the same names under [data-theme="dark"] rather than a second stylesheet.

12How does dark mode work here?

theme.js sets data-theme on <html> before paint. tokens.css defines the palette on :root and redefines the same variable names under [data-theme="dark"]. Because no component uses a literal colour, flipping one attribute re-themes everything.

13Flexbox vs Grid — when do you use each?

Flexbox is one-dimensional and content-driven: toolbars, button rows, card internals. Grid is two-dimensional and layout-driven: you define the tracks and place content into them. Synora's navbar needs Grid because only 1fr auto 1fr centres the middle group independently of how wide the outer two are.

14Explain grid-template-columns: minmax(0, 1fr) auto minmax(0, 1fr).

Three tracks. The outer two are equal and free to shrink to zero; the middle sizes to its content. Equal outer tracks are what actually centre the middle one. The minmax(0, …) removes the automatic min-content floor that would otherwise force the page wider than the viewport.

15Why does 1fr cause overflow?

1fr means minmax(auto, 1fr), and auto as a minimum is the content's min-content size. A wide table or <pre> then refuses to shrink and pushes the whole grid wider. minmax(0, 1fr) lets it shrink so the content scrolls in its own box instead.

16How is the responsive attendance grid done without a media query?

repeat(auto-fill, minmax(min(100%, 260px), 1fr)). The browser fits as many 260px columns as it can and reflows on its own. min(100%, 260px) stops the 260px floor overflowing a 320px screen.

17What is the CSS box model?

Content, padding, border, margin. Synora sets box-sizing: border-box globally so a declared width includes padding and border, which makes layout arithmetic predictable.

18Explain specificity.

Inline styles > id > class/attribute/pseudo-class > element. Ties are broken by source order. Synora stays mostly at the single-class level so overriding never needs !important.

19What is color-mix() used for here?

The translucent sticky header: color-mix(in srgb, var(--color-bg) 82%, transparent). It blends in CSS while still tracking the theme variable — a hard-coded rgba() could not follow the theme.

20What does clamp() do?

clamp(min, preferred, max) — fluid sizing with hard limits. Headings use clamp(1.75rem, 4vw, 2.25rem), scaling with the viewport without a media query.

21How do you hide something visually but keep it for screen readers?

The .visually-hidden pattern: 1×1 size, overflow: hidden, clip, and a negative margin. It stays in the accessibility tree, unlike display: none.

22What is :focus-visible and why prefer it to :focus?

It matches only when the browser judges a focus ring useful — typically keyboard, not mouse. Keyboard users keep the indicator; mouse users don't get a ring after every click.

23How does the CSS-only mobile menu work?

A visually hidden checkbox sits before the nav in the DOM. The <label for> is the visible button; clicking it toggles the checkbox, and .nav-checkbox:checked ~ .nav-panel reveals the panel. Order matters because the sibling combinator only looks forwards.

24How was the progress ring drawn?

An SVG circle with stroke-dasharray set to its circumference and stroke-dashoffset set to C × (1 − fraction). Offsetting one full-length dash reveals exactly the fraction wanted, and a CSS transition on the offset animates it.

25A bug: the ring collapsed to zero width. Why?

base.css gives every <svg> max-width: 100%. Inside a shrink-to-fit grid that is circular — the SVG waits on the container and the container waits on the SVG. It resolved to zero. Because the SVG was rotated −90°, its bounding box still measured 128 across, so it looked nearly right. Fix: state the wrapper's size explicitly.

26Why did text overlap the ring, and how was it fixed?

The value and label were inline spans in an absolutely positioned box with no layout, so they ran onto one line and spilled over the stroke. Fixing it meant stacking them in a flex column and capping the column at the ring's inner diameter — 128px minus two 12px strokes leaves ~104px clear.

JavaScript 16 questions

27Why an IIFE around every script?

It creates a private scope. Variables inside cannot leak onto window or collide with another file's, and only the chosen public API is attached to the single Synora namespace. With no bundler and no ES modules, this is how you get encapsulation.

28What is a closure? Give one from this project.

A function that keeps access to variables from the scope it was defined in, after that scope has returned. In attendance.js, setCounts still reaches the module's private helpers although the IIFE finished long ago. Onboarding's draft object is another: every step handler closes over the same object.

29What is event bubbling?

An event fires on the target, then propagates up through its ancestors to the document. It is what makes event delegation possible.

30What is event delegation and why is it necessary here?

One listener on a stable ancestor handling events from descendants, identified with e.target.closest(). Synora's grids re-render on every change, so listeners bound to buttons would be attached to elements about to be destroyed — and re-binding on each render would stack duplicate handlers that fire two, three, four times.

31Difference between e.target and e.currentTarget?

target is what was actually clicked; currentTarget is the element the listener is on. In delegation they differ, which is the whole point.

32== vs ===?

== coerces types before comparing; === compares type and value. Always === unless a deliberate == null check for both null and undefined.

33What is hoisting?

Declarations are processed before execution. var is hoisted and initialised to undefined; function declarations are hoisted whole. Synora declares variables at the top of each function so the written order matches the real order.

34How do you convert objects to and from storage?

JSON.stringify to write, JSON.parse to read — localStorage stores strings only. The parse is wrapped in try/catch, because a corrupted value should return a default rather than crash the page.

35map, filter, reduce — what does each do?

map transforms each item into a new array of the same length; filter keeps items passing a test; reduce collapses an array to one value. Synora builds HTML with map(…).join(""), selects tracked subjects with filter, and totals credits with reduce.

36What is a Promise, and where is one used?

An object representing a value that will exist later, with .then() for the result. Synora.confirm() returns one that resolves true or false, so a caller can await the user's answer without nested callbacks.

37What are custom events, and why use one?

new CustomEvent(name) plus dispatchEvent lets unrelated scripts communicate without importing each other. app.js announces synora:ready and every feature script listens — the shell doesn't need to know which pages exist.

38Why must synora:ready wait for DOMContentLoaded?

Deferred scripts run while readyState === "interactive", and feature scripts execute after app.js. Dispatching immediately would fire the event before any listener was registered, and nothing would render.

39How is XSS prevented?

Every user-supplied string passes through escapeHTML() before being concatenated into innerHTML, converting & < > " ' into entities. Otherwise a task titled <img src=x onerror=alert(1)> would execute when rendered — stored XSS.

40Why parse dates manually instead of new Date(string)?

new Date("2026-08-19") is parsed as UTC midnight, which in a positive timezone is still the 18th locally — deadlines would appear a day early. Synora splits the string and calls new Date(y, m - 1, d) for a local date.

41What does Array.prototype.some do here?

Returns true as soon as one item passes, short-circuiting. Used for duplicate-name detection and for the notification key check.

42What is the difference between null and undefined in this codebase?

undefined means a value was never set; null is an explicit "nothing". profile.avatar is null to mean "deliberately no avatar chosen", which is different from a key that does not exist.

LocalStorage & data 7 questions

43What is localStorage, and how does it differ from sessionStorage and cookies?

A synchronous per-origin key–value store of about 5–10 MB that persists until cleared. sessionStorage is the same API but dies with the tab. Cookies are much smaller (~4 KB) and are sent with every HTTP request, which localStorage never is.

44Why does only one file touch localStorage?

If eleven scripts called it directly, eleven scripts would each need to agree on key names, JSON shape, defaults and error handling. Funnelling through storage.js means the shape is defined once and corruption is handled once.

45How does Synora achieve per-user isolation?

Namespaced keys: synora:<username>:<collection>. Two accounts write to different keys, so isolation is structural rather than a filter someone could forget. The only global keys are the user list, the session pointer and the theme.

46What happens if stored JSON is corrupted?

readJSON catches the parse error, warns to the console and returns the default for that collection. A bad value degrades one feature instead of breaking the page.

47How do old accounts survive a schema change?

Object-shaped collections are merged with the current defaults on read, so keys added later appear with sensible values. subjects.all() goes further and normalises each record — a subject saved before trackAttendance existed is read as tracked, because that is what it was doing.

48Why compute CGPA and attendance instead of storing them?

A stored derived value is a second copy that can disagree with its inputs. Counts and grades are stored; percentages and averages are recomputed on every render, so they cannot drift.

49How is the demo data prevented from leaking into new accounts?

Seeding is gated on identity and a one-time flag: Synora.demo.isCurrent() && !meta.demo. An earlier version seeded for anyone signing in, which gave every new account a fake task history.

Authentication 7 questions

50Walk through the sign-up flow.

Validate all six fields; check the username is not taken; hash the password; push the account into synora-users; write synora-session; create an empty profile with onboarded: false; then show the confirmation screen and stop, offering Personalize or Dashboard.

51How are passwords stored, and is it secure?

Hashed with cyrb53, a fast non-cryptographic hash, so plaintext is not sitting in storage. It is not secure — no salt, fast to brute-force, and readable by anyone with the browser. Real auth needs a server and a slow salted hash like bcrypt or argon2.

52Why was the "already signed in" bar removed from the sign-in page?

It answered a question nobody on a sign-in page asked, and it displayed the account holder's real name on a screen anyone can open. The sign-in page is now a sign-in form and nothing else.

53Did removing it break the session?

No — and this distinction matters. Only the display was removed. The session is still written on sign-in and read by every app page; it is what the sidebar, Settings and the profile menu show. Signing out moved to the app's profile menu, where a signed-in person would look for it.

54Why does the confirmation screen not redirect automatically?

It used to show for 900 ms then navigate, which is an announcement rather than a choice. It now offers two buttons and waits. Both are plain <a href> links, so neither can be broken by a script that failed to run.

55What is the auth guard, and what changed about it?

Every app page checks for a session and redirects to sign-in if there is none. There used to be a second gate forcing unfinished setups back into onboarding — which made both "Go to dashboard" and "Save & finish later" bounce you straight back. It was removed; the dashboard now offers a finish-setup card instead.

56Why is the email regex deliberately loose?

Anything stricter starts rejecting perfectly valid addresses. Validation catches typos; only sending mail proves an address exists.

Onboarding & avatars 10 questions

57Why does onboarding exist?

A new workspace is empty by design, and an empty dashboard is a poor first impression. Six short questions produce a dashboard that already knows who you are and what you study — and the subject list it collects is what every other feature is built on.

58Why one question per step?

The same six fields in one long form reads as paperwork. Split up, it reads as setup — and each step can validate and explain itself.

59How is onboarding state managed?

An explicit draft object holds every answer, and the rendered step is a view of it. The DOM is never the state, so moving back and forth cannot lose an answer. The draft is mirrored to synora:<username>:onboarding on every change, so a mid-setup reload resumes on the same step.

60What does "Skip for now" do versus "Save & finish later"?

Skip moves past an optional step — only the avatar step is skippable. Save & finish later stores everything entered and opens the dashboard without marking setup complete, leaving the draft so you can return.

61Why couldn't avatars be selected, and how was it diagnosed?

An invisible full-screen overlay (.ob-done) sat above everything, so clicks never reached the radios. It was found with document.elementFromPoint(), which returned div.ob-done instead of the avatar — proving a hit-testing problem rather than a logic one.

62How is the avatar stored?

As { type, id } — {type:"illustration", id:"avatar-03"} or {type:"initials", id:"sage"}, or null. It used to be a bare id string, which could only describe one kind of avatar once a second kind existed.

63Where do the illustrations come from and what is the licence?

The Lorelei style from DiceBear, by the designer Lisa Wischofsky, under CC0 1.0 — public domain, no attribution required. They were generated once and committed to assets/avatars/ rather than fetched at runtime, so they work offline and send nothing about the user to a third party.

64Is it correct to say "DiceBear avatars are CC0"?

No. The library code is MIT, but each style is licensed separately by its artist. Lorelei is CC0; several others are CC-BY-4.0 and need visible credit. Only the licence of the style actually used may be claimed.

65How are initials derived, and why one function?

Synora.util.initials(first, last) takes the first letter of the first name and the first letter of the last name — "Manan Kochhar" → MK, never MA. It is defined once in storage.js and used by the sidebar, topbar, dashboard, Settings and onboarding, so two screens cannot disagree.

66Why six colours for the initials avatar rather than six greens?

Six shades of the brand colour is not a choice. The set spans the whole Synora palette — sage, ink, taupe, slate, clay, mist — each paired with a foreground that clears WCAG AA for large text.

Subjects & attendance 12 questions

67Why are subjects the source of truth?

If attendance, CGPA and the timetable each stored their own copy of "DBMS", renaming it in one place would leave three modules pointing at a name that no longer exists. They store a subjectId and resolve the name at render time, so a rename propagates everywhere with no records touched.

68What is trackAttendance and why was it added?

A per-subject boolean deciding whether the subject appears in Attendance. Some subjects genuinely don't take a register — a one-credit elective, an audit — and forcing them onto the page produced a permanent 0% and a recurring "is at 0%" notification for a class nobody counts.

69Does trackAttendance: false affect the CGPA?

No, and that is the point. It controls Attendance only. Credits, grade and CGPA contribution are untouched, and the subject still appears on the CGPA page and its chart. Attendance and CGPA are independent systems.

70How is an untracked subject kept out of attendance warnings?

The notification pass walks derive.attendance(), which itself iterates subjects.tracked(). An untracked subject can never reach the loop — it is unreachable by construction rather than filtered out afterwards.

71Why does attendance iterate subjects rather than the stored attendance rows?

So the subject list is the definition of what attendance covers. A new subject appears instantly at 0/0 with working buttons, and switching tracking off removes it from the page, the chart and the warnings at the same moment, with no stale row to clean up.

72What are the attendance invariants and where are they enforced?

held ≥ 0 and 0 ≤ attended ≤ held, both inside setCounts(). Putting them in one function means the +, the − and the Edit dialog cannot disagree. Lowering held pulls attended down with it, because you cannot attend a class that was not held.

73What happens when held = 0?

The percentage is guarded: total ? (attended / total) * 100 : 0. The card shows "No classes recorded yet" rather than NaN, Infinity, or a misleading 0%.

74Why is there no "Track a subject" button on the attendance page?

A subject is not something you add there; it is something you already have, which either takes a register or doesn't. A second way to create subjects would create a second list to disagree with the first.

75Why are credits hidden on the attendance page?

Credits are a CGPA fact. They say nothing about whether you turned up, and showing them made each row carry a number irrelevant to what it was about.

76Derive the "how many can I miss" formula.

You stay at or above the goal while attended / (held + x) ≥ goal/100. Solving for x: x ≤ attended×100/goal − held, floored and clamped at zero.

77Derive the "how many must I attend" formula.

Attending n in a row gives (attended + n) / (held + n) ≥ goal/100. Solving: n ≥ (goal×held − 100×attended) / (100 − goal), ceilinged. Note it breaks down at goal = 100, which the code special-cases.

78Why is the attendance chart fixed at 0–100%?

A percentage has a real ceiling. A chart auto-scaled to the tallest bar would make 83% look like a full house. The dashed target line reads profile.targetAttendance and is never hard-coded to 75.

CGPA 9 questions

79State the CGPA formula.

CGPA = Σ(credits × grade point) / Σ(credits). Credits come from the subject record, grade points from the grading table.

80List the grading system.

Passes: O = 10, A+ = 9, A = 8, B+ = 7, B = 6. Failures: E1 = failed internals, E2 = failed end-term, E3 = failed both — all worth 0 points.

81How do failing grades affect the CGPA?

They earn zero grade points but their credits still count in the denominator, which is what drags the average down. This is a stated assumption of the project, not a universal rule — there is no university-specific rule here to defer to.

82Why was the separate "Exam status" field removed?

It duplicated the grade. Two controls described one outcome, and nothing stopped them contradicting each other — a subject could read "A+" and "failed both" simultaneously. The grade now carries the result on its own.

83Why was the 4.0 US scale removed?

E1/E2/E3 are specific to this grading system. Offering them alongside a US scale produced combinations that meant nothing, and two scales doubled the chart logic for no benefit.

84Explain the split chart.

Above the baseline are the passing grades on a ladder read upwards (B → B+ → A → A+ → O). Below it hang the three failure states. They are separated because a failure is not a small grade — putting E1 on the same upward scale would say something false.

85Why not label the negative axis "E1/E2/E3"?

Because which examination was failed is the entire point of the distinction. A merged label throws away the only information the three values carry.

86Does an untracked subject appear on the CGPA chart?

Yes. Every graded subject does. Attendance is about registers; CGPA is about credits and grades.

87How are long subject names handled on the x-axis?

Each label carries a title tooltip with the full name, and the chart scrolls inside its own overflow-x: auto container. The page body itself never scrolls sideways.

Tasks, calendar, notes, timetable 7 questions

88What fields does a task have?

id, title, subject, description, deadline, priority (critical/high/medium/low), status (not-started/in-progress/completed), createdAt and completedAt.

89Why is "overdue" not a stored field?

It would be wrong the moment the clock passed midnight. It is computed from the deadline on every render instead.

90How is the calendar grid built?

new Date(y, m + 1, 0).getDate() gives the number of days in the month (day 0 of the next month is the last of this one), and new Date(y, m, 1).getDay() gives the weekday the 1st falls on, which becomes the count of leading blank cells.

91How are tasks matched to calendar days?

Deadlines are stored as YYYY-MM-DD strings, so matching is a string comparison — no timezone arithmetic and no ambiguity.

92Why are timetable times stored as 24-hour zero-padded strings?

Because "09:00" < "11:00" then sorts correctly as plain text, so a day's classes order themselves with no parsing.

93How does the dashboard know today's classes?

It maps new Date().getDay() through a day-name array, filters the timetable to that day, resolves each subjectId to a name, drops entries whose subject was deleted, and sorts by start time.

94What is the difference between app/notes.html and the root notes.html?

app/notes.html is the Quick Notes feature inside the product. The root notes.html is this study document — standalone, with no connection to the app.

Achievements & notifications 6 questions

95How are achievements evaluated?

Each declares a measure(ctx) function and a goal. After every data change the engine rebuilds the context from stored data and unlocks anything now meeting its goal, so a badge can never disagree with the data behind it.

96Why store the unlock date?

So a badge stays earned even if the underlying data later changes. Deleting old tasks should not take back something you actually did.

97How is the streak calculated?

Consecutive days with at least one completion. It only counts as live if the last completion was today or yesterday; otherwise the streak is broken and reads zero.

98How are duplicate notifications prevented?

Each carries a stable key and add() refuses one whose key already exists. Because the deadline is part of the key, changing a deadline correctly produces a new alert rather than being swallowed as a duplicate.

99What does "reconciling" notifications mean?

Attendance warnings are not only added — each pass computes which subjects are genuinely below target and drops any older attn: alert not in that set. So fixing attendance, editing the subject, untracking it or deleting it clears the warning instead of leaving it stuck.

100Difference between read and seen?

seen means the bell was opened and clears the red count. read means the item was dealt with and un-bolds the row. "I glanced at the bell" and "I have handled this" are different statements.

Design, UX & accessibility 7 questions

101How is the design system organised?

tokens.css (variables) → base.css (reset and elements) → components.css (shared primitives) → page stylesheets. Later files may use earlier tokens but never redefine them.

102Name the palette and its intent.

Ink #22252B for headings and dark bands, Sage #53655C as the brand, Slate #A3AEB1 for dividers and quiet icons, Mist #E5E8EB for borders, Taupe #B09F95 as a warm accent. Five colours used deliberately, rather than one hue everywhere.

103How does Synora avoid relying on colour alone?

A selected avatar shows a border, a tick and a background. A subject below target shows a red percentage, a coloured card edge and a sentence explaining it. Anyone who cannot distinguish the colour still gets the message.

104How are charts made accessible?

Each carries role="img" and an aria-label stating every value as a sentence, plus a visible caption explaining how to read the axes.

105Why are the avatar radios hidden with opacity rather than display: none?

display: none removes an element from the tab order, which would lose keyboard focus and the arrow-key navigation a radio group provides. Shrinking it to 1×1 with opacity: 0 keeps all of that.

106Where is focus managed explicitly?

Each onboarding step moves focus to its heading (with tabindex="-1"), the confirmation screen focuses the first choice, and modals focus their first field. Otherwise focus would stay at the top of the document after content changed.

107How is motion handled for users who don't want it?

A prefers-reduced-motion: reduce block disables animations and transitions, and the onboarding finish shortens its delay instead of playing a transition.

Testing, limitations & scope 6 questions

108How was this tested without a framework?

Systematic manual verification of every flow, plus checks run in the browser console — reading computed styles and bounding boxes, asserting the stored JSON after each action, and loading all ten app pages while watching for console errors.

109Name three bugs found and their root causes.

(1) Onboarding entirely unclickable — a CSS display: grid overriding the hidden attribute left an invisible overlay. (2) The progress ring collapsed to zero width — svg { max-width: 100% } created a circular sizing dependency inside a shrink-to-fit grid. (3) Stuck "0%" attendance alerts — warnings were added but never retired, fixed by reconciling them each pass.

110How do you check for horizontal overflow?

document.documentElement.scrollWidth > window.innerWidth in the console. If true, something is wider than the viewport — usually a grid track without minmax(0, …).

111What are the project's main limitations?

No backend, so no real authentication and no sync; data is per-browser and per-device; localStorage is capped at a few megabytes and writes synchronously; the contact form sends nothing; and the demo credential is sample data, not a security claim.

112What would you add next, and why that first?

A backend with real accounts. It is the prerequisite for everything else worth having — sync, real security, sharing — and it is the honest answer to the project's biggest limitation. Import/export would be the cheapest useful win before that.

113Why no framework?

The point of the exercise is to build the mechanisms rather than import them: state management, DOM updates, event delegation, routing between pages. A framework would hide exactly the parts being demonstrated — and at this size it would add a build step and a dependency tree for no benefit.
